# ADR-0004：Fn / 🌐 键组合的接管策略

- 状态：已采纳（2026-11-02）；**同日更正**：原结论基于一个 bug 得出，已推翻，见下方「更正」
- 日期：2026-11-02

## 背景
用户希望把 Fn 与其他修饰键任意组合成全局快捷键（例如 `fn+a` 打开活动监视器）。
难点：
1. 系统会给方向键、F1–F12、Home/End 等键**自动**加上 Fn 标志位，不能只凭标志位判断用户是否按了 Fn。
2. 新款 Mac 的 🌐 键自带一批系统快捷键（🌐E 表情、🌐F 全屏、🌐A 聚焦程序坞、🌐C 控制中心、🌐N 通知中心、🌐Q 快速备忘录……），可能在 event tap 之前就被系统处理。
3. 单独按下 🌐 键会触发"切换输入法 / 显示表情 / 听写"等动作（系统设置 → 键盘 → "按下 🌐 键时"）。如果我们吞掉了 `fn+a` 中的 `a`，系统可能认为 🌐 被"单独按下"，在松开时触发这个动作。

## 当前实现（M0）
- `KeyNormalizer` 通过 flagsChanged（键码 63）跟踪 Fn 的**物理**按下状态；仅在没观察到 Fn 的 flagsChanged 时，才对"不会被自动加 Fn 位"的键信任标志位。
- Event tap 位于 `kCGHIDEventTap` + `headInsertEventTap`，是用户态能拿到事件的最早位置。

## ⚠️ 更正（2026-11-02，M1 期间）

下面"实验记录"中的结论**是错的**。当时 MAIO 的 event tap 回调写成了
`self?.handle(...) ?? Unmanaged.passUnretained(event)`：`handle` 返回 nil 表示"吞掉事件"，
但可选链把这个 nil 当成"self 不存在"，于是事件被原样放行。**MAIO 从来没有真正吞掉过任何按键或滚动事件。**
所以实验 2 中"MAIO 吞掉了 Q 但备忘录仍然弹出"的前提不成立。

修复后重新验证（合成事件，🌐Q 临时开启）：

| 实验 | 结果 |
|---|---|
| fn+Q（只有带 Fn 位的 Q），MAIO 运行 | 只打开 Otty，**快速备忘录不弹出**（2/2） |
| 完整序列 Fn 按下 → Q → Fn 松开，MAIO 运行 | 只打开 Otty，快速备忘录不弹出 |
| 窗口探针：先按 x（未绑定），再按 fn+Q | 窗口只收到 x，q 没有漏进前台 App |

**正确结论**：系统 🌐 快捷键在 HID 层 event tap **之后**处理。MAIO 运行时可以接管与系统 🌐 快捷键相同的组合；
MAIO 退出后，系统快捷键恢复工作。实验 E3/E4（系统依据"带 Fn 位的按键事件"识别 🌐 快捷键）仍然成立。

防止再犯：`scripts/check-architecture.sh` 新增规则，禁止 `?.xxx(...) ?? Unmanaged.passUnretained` 写法。

待用户用真实键盘确认（合成事件与硬件事件走同一条管线，预期一致）。

## 实验记录（2026-11-02，结论已被上方更正推翻）

脚本在 `kCGHIDEventTap` 注入合成事件，以"前台 App 是否变成备忘录"作为判断依据：

| 实验 | 注入内容 | MAIO | 快速备忘录 |
|---|---|---|---|
| 1 | Fn 按下 → Q（带 Fn 位）→ Fn 松开 | 未运行 | 弹出 |
| 2 | 同上 | 运行，日志显示已触发并吞掉 Q | **仍然弹出** |
| E3 | Fn 按下 → Q（**不带** Fn 位）→ Fn 松开 | 未运行 | 不弹出 |
| E4 | 只有 Q（带 Fn 位），没有 Fn 的 flagsChanged | 未运行 | 弹出 |

`CGGetEventTapList` 显示 MAIO 的 tap 是全系统**第一个**键盘 tap（HID 层，排在微信输入法、PixPin、BetterDisplay 之前）。

**结论**：系统 🌐 快捷键依据"带 Fn 标志位的按键事件"判断，并且是 WindowServer 在**所有 event tap 之前**处理的。
任何 CGEventTap 方案（包括 MAIO 当前实现）都无法阻止系统 🌐 快捷键，只能和它们"同时执行"。
不与系统 🌐 快捷键重叠的 Fn 组合（例如 `fn+s`）不受影响。

"快速备忘录"等 🌐 快捷键出现在系统设置的"键盘快捷键"列表中（`KeyboardSettings.appex` 的 `DefaultShortcutsTable`），可以由用户关闭。

## 备选方案（按代价从低到高）
1. 引导用户把"按下 🌐 键时"设为"无操作"，并在系统设置 → 键盘快捷键中关掉冲突的 🌐 快捷键。
2. 在吞掉 Fn 组合时补发一个无副作用的事件，让系统认为 🌐 不是被单独按下（类似 Karabiner 的 `vk_none`）。
3. 使用 IOHIDManager 在 HID 层监听。
4. 引入 Karabiner DriverKit 虚拟键盘（代价最高）。

## 决定（2026-11-02，已按更正修订）

1. **不做驱动层改写**。HID 层 event tap 足以接管系统 🌐 快捷键（见更正）。
2. **冲突检测**：保存 Fn 组合绑定时，用 `CGSGetSymbolicHotKeyValue` / `CGSIsSymbolicHotKeyEnabled`（SkyLight 私有函数，通过 dlsym 动态加载，失败时降级为不检测）
   查询是否与**已启用**的系统 🌐 快捷键重叠，提示"覆盖系统快捷键 XX（MAIO 运行时接管）"。
3. **可选禁用**：希望退出 MAIO 后也不触发时，可以禁用系统快捷键（带备份、一键恢复，见 ADR-0005）。
4. 系统默认 🌐 快捷键清单见 `docs/reference/system-globe-shortcuts.md`。

已验证：用户在系统设置中关闭"快速备忘录"后，MAIO 的 `fn+q` 正常工作，不再弹出备忘录。
