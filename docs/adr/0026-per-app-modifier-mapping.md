# ADR-0026：按 App 改修饰键（前台 App 切换时临时改写键盘服务的修饰键映射）

- 状态：已采纳
- 日期：2026-11-18
- 补充：ADR-0022（改键分层）

## 背景

用户在 Mac 上玩英雄联盟（游戏进程 `com.riotgames.LeagueofLegends.GameClient`），Windows 上的习惯是"Ctrl + 技能键 = 加点"。
用户的自带键盘从左到右是 ⌘ ⌃ Fn ⌥（设备级映射，ADR-0022），最左边的键在游戏里是 ⌘，按 Ctrl 加点就按成了 ⌘ 快捷键（甚至 ⌘Q 退出）；
Mac 版游戏又不能把 ⌘ 设成游戏内快捷键。用户要的是：**在指定的 App 里，把修饰键 A 换成 B，可以配多条**（例如游戏里 ⌘ ↔ ⌃ 对调）。

查过游戏的二进制：它读键盘用 AppKit（`keyDown:`、`flagsChanged:`、`modifierFlags`），没有用 IOHIDManager。
但 `modifierFlags` 也可能是类方法（直接查询当前修饰键状态），event tap 改写事件对这种读法无效。

## 决定

1. **在 HID 层做**：前台 App 命中规则时，给每个接着的键盘临时设一份"设备映射 ∘ App 规则"合成的
   `HIDKeyboardModifierMappingPairs`（服务属性，**不写偏好**）；离开这个 App 时设回设备映射。
   - 规则作用在"设备映射之后的修饰键"上：自带键盘最左边的键设备映射成了 ⌘，规则 ⌘ → ⌃ 就把这个键在游戏里变成 ⌃。
     合成后仍是一份服务属性，不存在和全局 `UserKeyMapping` 先后顺序的问题。
   - 设备映射优先读偏好（系统设置的修饰键设置）；没有偏好的键盘用第一次改写之前的服务属性，记在内存里。
2. **等修饰键全部松开再切换映射**：映射在按住修饰键时改变，松开时会发出另一个键的松开，修饰键可能卡住
   （例如在游戏里按住 ⌘ 切出去）。轮询 `CGEventSource.flagsState(.hidSystemState)`，松开后再切。
3. 规则的来源只有 ⌃ ⌥ ⌘ 🌐（Caps 由 Super Caps 管），目标是 ⌃ ⌥ ⌘ 🌐、Esc、无操作。按 bundle ID 精确匹配前台 App。
4. 只用已有的 `SystemEventService.frontmostApplicationChanges()`，不改 MAIOKit。

## 备选方案

- **event tap 里改写事件的修饰键标志和修饰键键码**：语义一样，但游戏用 `NSEvent.modifierFlags` 类方法或
  `CGEventSourceFlagsState` 查询时拿到的是硬件状态，对调失效；鼠标事件上的修饰键标志也改不到。还要给 MAIOKit 的过滤器加"原地改写"的能力。
- **切换全局 `UserKeyMapping`**：和设备级映射叠在一起时先后顺序不确定（要实验），规则语义会随键盘不同而变。

## 后果

- 规则对所有接着的键盘生效，游戏里任何读法都能看到改后的修饰键。
- MAIO 在游戏前台时崩溃 / 被强制退出：有系统修饰键设置的键盘，MAIO 下次启动时按偏好恢复；
  没有设置过的键盘保留改写后的映射，直到重新接上（或重新登录）。
- 游戏前台时新接上的键盘不会被改写，切换一次 App 后生效。
- 设置页「键盘重映射」在规则生效期间改动键盘，会覆盖临时映射，直到下次切换 App。
