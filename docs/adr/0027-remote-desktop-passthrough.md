# ADR-0027：远程桌面 App 在前台时让出快捷键和改键

- 状态：已采纳
- 日期：2026-11-19
- 关联：ADR-0003（输入引擎）、ADR-0013（被控端的远程滚动）、ADR-0017 / ADR-0023（按键、按钮过滤器）

## 背景
用户用网易 UU 远程控制公司的 Windows 电脑，两边的功能（启动台、窗口切换、剪贴板、截图……）按同样的物理键位设置，
靠肌肉记忆使用。但 MAIO 的键盘 tap 在 HID 层最前面，⌘Space、⌥Tab 这些键在 UU 拿到之前就被 MAIO 吞掉、
在本机执行，远程电脑收不到。逐条给绑定设"除以下 App 外"太麻烦，以后新加的功能还要再设一遍。

ADR-0013 处理的是反方向（别人远程控制这台 Mac），按事件来源进程判断；这里是这台 Mac 控制别人，按前台 App 判断。

## 决定
- 名单里的 App 在前台时，输入引擎（`KeyboardRouter`、`ButtonTap`）对按下的键 / 按钮直接放行：
  快捷键表、按键过滤器（Super Caps、其他改键、Finder 增强）、按钮过滤器都不执行。判断在引擎里做，功能不需要知道。
- 仍然照常的：已在进行的键盘会话、快捷键录制；进入远程前已被吞掉按下的键，松开时照样吞掉；
  修饰键变化照常通知过滤器（避免过滤器记录的修饰键状态错乱）；HID 层的改键（`UserKeyMapping`、设备修饰键映射、
  ADR-0026 按 App 改修饰键）和指针（滚轮）过滤器不受影响。
- 设置存在 `config/remote-desktop.json`（`RemoteDesktopSettings`：开关 + bundle ID 名单，默认打开，带常见远程软件），
  由 `MAIOCore/Host/RemoteDesktopMode` 读写，界面在「通用 › 远程桌面」。不放进 `app.json`：那个文件由 `FeatureHost` 独占读写，
  加非可选字段会让旧文件解码失败。
- 不改 `MAIOKit`。

## 备选方案
- 每条绑定的"生效范围"里排除远程 App：已经能做，但要逐条设，新功能还要再设，改键也管不到。
- 按功能各自判断：违背"引擎统一处理"，每个功能都要改。
- 给绑定加"远程时也生效"（逃生键）：要改 `MAIOKit` 的 `CommandBinding`，用户决定先不做。

## 后果
- 远程时 MAIO 的键盘功能全部让出。Caps 在全局被设成"无操作"（HID 层），远程电脑收不到 Caps，Caps+键会以普通键发出。
- ⌘Space 等 MAIO 只在运行时"接管"、系统设置里没禁用的系统快捷键，放行后可能被系统处理（例如弹出聚焦），没实测。
- 名单外的远程软件、虚拟机要用户自己加。
