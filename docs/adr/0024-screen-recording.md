# ADR-0024：录屏（MP4 / GIF）

- 状态：已采纳
- 日期：2026-11-08

## 背景

用户要求在截图里加上录屏：能录 MP4 和 GIF，MP4 可以选择录系统声音和麦克风，**性能优先**。
用户定下的交互（2026-11-08）：
- 入口两种都要：截图框选后按工具栏按钮或 ⌘R；另有独立命令 `screenshot.record`（默认 ⌥F3）；
- 录完存到文件夹，同时把文件复制到剪贴板；
- 两路声音混成一条音轨；
- MP4 编码在设置里可选，默认 H.264。

常见做法（例如基于 Qt 的同类截图工具）：
- 用 ScreenCaptureKit 的 `SCStream` 抓画面和系统声音；
- 每一帧先转成通用图片对象，再交给自带的 FFmpeg / OpenH264 编码器。

这条路线多了一次整帧拷贝和格式转换，我们不需要。

## 决定

1. **一个 `SCStream` 提供画面和系统声音**（`capturesAudio`）；**麦克风直接从设备采集**（`AVCaptureSession` + `AVCaptureAudioDataOutput`，`MicrophoneCapture`）。
   - 不用 `SCStream` 的 `captureMicrophone`：实测（2026-11-08，macOS 27）它给的麦克风数据里**混进了系统声音**。只开麦克风、戴耳机播放提示音，流里的峰值 0.33；直接读设备只有约 0.05（耳机漏音）。用户也反馈只开麦克风时能录到系统声音；
   - 时间戳都换算到主机时钟（`CMSyncConvertTime`），不需要另外对齐；
   - 所有回调都放在写入器的同一个串行队列上，不用加锁；
   - 排除 MAIO 自己的窗口和声音，控制条、边框不会被录进去；
   - 只接收 `SCFrameStatus.complete` 的帧。画面没变时系统不发新帧，静止画面几乎不耗 CPU。
2. **MP4：零拷贝硬件编码**。
   - 流直接输出 4:2:0 YUV（`420v`，BT.709），`CMSampleBuffer` 原样交给 `AVAssetWriterInput`，由硬件编码器处理；
   - 帧率可变（只写有变化的帧），结束时 `endSession` 到停止时刻；
   - 编码默认 H.264，可选 HEVC。不用 B 帧，关键帧间隔 2 秒；
   - 码率按 宽 × 高 × 帧率 × 每像素比特（H.264 0.12，HEVC 0.08）计算，限制在 2～60 Mbps；
   - H.264 硬件上限是一帧 4096×2304 个像素，超过时等比缩小（`RecordingGeometry`）。HEVC 上限 8192×4320。
3. **声音混成一条 AAC 音轨**（`AudioMixer`，纯逻辑，有单测）。
   - 每路先统一成 48 kHz 浮点立体声，麦克风必要时用 `AVAudioConverter` 重采样；
   - 按"从录制开始第几个采样"对齐。相邻两段间隔 ≤2 ms 视为连续，更大的缺口补静音；
   - 两路都写到的部分立即混出。某一路一直没有数据（没在放声音）时最多等 0.2 秒，然后当作静音；
   - 相加后限制在 -1～1。
4. **GIF：自己写的流式编码器，边录边编**（`Domain/Recording/GIF/`，不依赖第三方库）。
   - 默认按 pt 录（比 Retina 像素少 4 倍），可在设置里打开高清；帧率默认 15，可选 10～30；
   - 流的回调只把最新一帧放进信箱。编码在单独的 utility 队列上，跟不上时中间帧丢掉，时间算进上一帧，播放速度不变；
   - 每帧只编码和上一帧不同的最小矩形。矩形里没变的像素记为透明，处置方式 1 透出上一帧；
   - 每帧自带调色板：
     - 颜色 ≤256 种时直接用原色，完全无损（界面、文字大多如此）；
     - 否则在 15 位直方图上做中位切分，不抖动（屏幕内容抖动后满屏噪点，文件也更大）；
   - LZW 用 8192 格的开放寻址码表。码长增长和解码器严格对齐，单测用系统 ImageIO 解码逐像素核对；
   - 编码好的一帧立即写盘，内存里只留上一帧的像素和一帧待写的数据；
   - 帧时长按绝对时间取整，不累积误差，最小 2/100 秒（更小的值很多播放器当成 1/10 秒）。
5. **交互**：
   - 选区外画虚线边框，下方是控制条：MP4 / GIF、系统声音、麦克风、开始；
   - 开始前用键盘会话接管 ⏎ / Esc。开始后立即交还键盘，录制中的按键照常打到其他 App；
   - 结束：控制条上的「完成」，或再触发一次 `screenshot.record`。「放弃」删除文件；
   - 结果存到录屏文件夹（默认 `~/Movies/MAIO`），文件复制到剪贴板。不写入截图历史。
6. **权限**：
   - 系统声音包含在「屏幕与系统录音」权限里；
   - 麦克风只在打开"录麦克风"时请求（`AVCaptureDevice.requestAccess`）；
   - 主程序要加 `com.apple.security.device.audio-input` entitlement（Hardened Runtime 下没有它会被直接拒绝）和 `NSMicrophoneUsageDescription`；
   - 麦克风权限不加进 MAIOKit 的 `Permission`：只有这一个功能用，也不是必需权限。

## 备选方案

- **`SCRecordingOutput`（macOS 15）**：系统直接写文件，代码最少。但不能把麦克风和系统声音混成一条音轨，也不能做 GIF，排除。
- **先录 MP4，结束后再转 GIF**：录制本身最省，但录完要等转换，还要多存一份中间文件。边录边编实测足够快：
  - 1440×900 整帧最坏情况（每个像素颜色都不同）约 28 ms；
  - 普通界面整帧 7 ms，局部变化不到 1 ms；
  - 录整屏在播放的视频，15 帧/秒也没有丢帧。
- **ImageIO 写 GIF（`CGImageDestination`）**：
  - 要等 finalize 才输出，所有帧都留在内存里；
  - 没有"只编码变化区域 + 透明"，文件大很多。
- **gifski / FFmpeg**：要引入第三方依赖（需要 ADR 白名单），体积大；我们的场景用不上它们的高质量抖动。
- **两条音轨**：有些播放器和网页只播第一条，用户选了混成一条。

## 后果

- 录屏不进截图历史，不能重新编辑。
- 录制中不能暂停（以后需要时再加：`AVAssetWriter` 要整体平移后续时间戳）。
- GIF 不录声音。录全屏视频这类内容 GIF 会很大，这是格式本身的限制。
- 截图模块加进了 Debug 也开 `-O` 的列表（GIF 编码、长截图匹配都是逐像素热循环）。
- 多显示器：选区所在的那台显示器。选区不能跨显示器，和截图一样。
