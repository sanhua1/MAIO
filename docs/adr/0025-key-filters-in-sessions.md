# ADR-0025：按键过滤器可以选择在键盘会话期间生效

- 状态：已采纳
- 日期：2026-11-12
- 修订：ADR-0017（过滤器的位置）

## 背景

ADR-0017 把按键过滤器放在"键盘会话之后"：会话（窗口切换、截图、快捷键录制）期间按键原样交给会话，过滤器看不到。

用户反馈（2026-11-12）：用 Mac 自带键盘 ⌥Tab 开始切换窗口后，按住 Caps + WASD 不会当方向键用。原因就是会话期间 Caps 层不生效，
切换器收到的是原始的 W/A/S/D——而切换器里 W 是"关闭窗口"、Q 是"退出 App"，所以 Caps+W / Caps+Q 还会误关窗口、误退出程序。

不能简单地让所有过滤器都在会话里生效：Finder 增强的过滤器在 Finder 位于前台时把 ⏎ 改成"打开"，
切换器、截图里的 ⏎ 就会被它改掉。

## 决定

1. `RealtimeKeyFilter` 新增属性 `appliesDuringKeyboardSessions: Bool`，协议扩展里默认 `false`（已有过滤器行为不变）。
2. 会话期间的 keyDown 只问 `appliesDuringKeyboardSessions == true` 的过滤器：
   - `replace(chord)`：**不发合成按键**，而是把改后的键（键码 + 修饰键）交给会话；对应的 keyUp 也按改后的键码交给会话；
   - `consume`：吞掉，不交给会话（例如 Caps 层里绑定的 MAIO 命令照常执行）；
   - `pass`：原样交给会话。
3. `FeatureKeys` 的 `KeyRemapFilter`（Caps 层 + 全局组合键改键）选择加入。理由：在用户看来 Caps+W 就是 ↑，
   和"单键换单键"在 HID 层生效、会话里本来就能看到改后的键一致。

## 后果

- 快捷键录制（也是键盘会话）期间按住 Caps+W 会录成 ↑，全局组合键改键（例如 Home → ⌘←）会录成改后的组合键。
  这和其他 App 实际收到的键一致，可以接受。
- 新写的过滤器默认不在会话里生效；要生效的必须保证改出来的键对任何会话都是"用户想按的键"。
