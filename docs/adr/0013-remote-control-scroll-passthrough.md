# ADR-0013：远程控制软件注入的滚动事件不经过指针过滤器

- 状态：已采纳
- 日期：2026-11-03
- 关联：ADR-0003（输入引擎）、ADR-0006（指针事件）

## 背景
用户通过网易 UU 远程控制这台 Mac 时，滚轮方向始终是反的。原因是远程软件在被控端注入的滚动事件没有手势阶段，被识别成普通鼠标滚轮，FeatureScroll 又把它反转了一次。但远程事件的方向和平滑已经由控制端电脑按自己的习惯处理过，被控端再处理只会出错。Mos 也有同样的处理：按来源进程识别远程软件并跳过。

## 决定
- 指针 tap（`MAIOCore/Input/PointerTap`）读取事件的 `eventSourceUnixProcessID`，来源进程的可执行文件路径包含远程控制软件关键字（屏幕共享、ARD、UU 远程、ToDesk、向日葵、TeamViewer、AnyDesk、Parsec、RustDesk、VNC）时，原样放行，所有过滤器都不执行。
- 判断在引擎里做，不改 `MAIOKit` 的 `PointerEvent`：远程输入对所有指针过滤器都应透明，不需要功能各自判断。
- 结果按 pid 缓存（只缓存最近一个），tap 线程上只在来源变化时调用一次 `proc_pidpath`。

## 备选方案
- 跳过所有其他进程注入的事件：会误伤 Logitech Options 等鼠标驱动发出的平滑滚动（这些应该照常反转）。
- 在设置里加"远程时不反转"开关：用户无法预知需要它，默认就该正确。

## 后果
- 名单外的远程软件仍会被反转，遇到时往关键字列表里加。
- 远程控制时，被控端的 App 例外、平滑设置都不生效（由控制端决定），这是期望的行为。
