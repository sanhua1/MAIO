# ADR-0020：启动器的文件搜索用自建全盘索引（以 oil-find 为蓝本）

- 状态：已采纳
- 日期：2026-11-05

## 背景

用户要求启动器的文件搜索"像 Windows 的 Everything"：输入任何关键词，文件名或路径包含它的结果即时全部列出。
Everything 靠直接读 NTFS 的 MFT，macOS 没有对应的东西。可选：用系统聚焦（Spotlight）的索引，或自建索引。
用户选择自建，并要求参考最成熟的开源实现。

## 调研（2026-11-05，`references/`）

| 项目 | 结论 |
|---|---|
| Cardinal（Rust，1.7k 星） | Everything 语法最完整；但核心是单线程逐个比对不重复的名字，不区分大小写时全走正则；名字池只增不减 |
| **oil-find**（Swift + 薄 C 层） | 工程质量最高：getattrlistbulk 并行扫描、名称连成一块 + SIMD、SoA 约 46 B/条、拼音备用键、FSEvents 处理严谨（事件库 UUID、先开流再扫描、子树重扫） |
| MacEverything（C++） | 反面教材：每个文件存完整路径（≥300 B/条）、三字母组倒排、目录改名不处理子树、回放和实时流之间有空窗 |

## 决定

1. **引擎照 oil-find 的思路用 Swift 重写**（MIT，借用处注明出处），代码在 `FeatureLauncher/Index/`：
   - 扫描：`getattrlistbulk`，N 个线程共用目录任务栈；只扫系统卷和数据卷；默认不进包（.app 等）、不进 iCloud 占位目录。
   - 存储（`IndexData`）：每个字段一个数组；**小写 + NFC 的名称首尾相接存成一块**（每个后面跟 0），原名和小写名不同时另存原名；
     编号 0 是 `/`，**父目录编号小于子项**（删除子树、压缩都只需扫一遍）；`(父目录, 名称) → 编号` 的开放寻址哈希表用于按路径找条目。
   - 搜索：最长的词用 libc `memmem` 分段并行扫名称块（和拼音键块），其余条件逐条过滤，按匹配质量 + 位置标志打分，小顶堆取前 N 条。
   - 增量：FSEvents 逐文件事件，每条事件重新 lstat，"不存在 → 删子树；新出现 → 补父目录链再加（目录扫一遍）；已存在 → 更新"；
     同一批里合并重复路径、要整棵重读的目录下的事件跳过（Cardinal 的最小祖先）；根路径丢事件、事件编号回绕时整盘重扫。
   - 存盘：`data/launcher/index.bin`，存压缩后的各数组 + 扫描设置指纹 + 事件编号 + 事件库 UUID；启动时都对得上就直接用并从事件编号回放，否则重扫。
     **全盘扫描前先记下事件编号并开始监视**，扫描期间的事件攒着、扫完补上。
2. **语法照 Cardinal**（P3 实现）。
3. **启动器模块 Debug 也开 `-O`**（`Package.swift` 的 `alwaysOptimized`）：实测 Debug（`-Onone`）下单字母搜索 4.1 秒、建索引 12.7 秒，开 `-O` 后 0.17 秒、0.7 秒。
4. 没有"完全磁盘访问"时跳过受保护的位置（不然每个位置弹一次授权），设置页提示；打开面板时检测到权限变化就按新范围重扫。

## 实测（本机，147 万条，`-O`）

扫描 8.5～10 秒（4～8 线程）；建索引 0.7 秒；索引约 90 MB（约 62 B/条）；读盘 0.31 秒；
搜索多数 4～40 ms，单字母 170 ms；新建文件 0.26 秒后可搜到，删除 0.14 秒后消失。

## 备选方案

- **Spotlight（NSMetadataQuery / mdfind）**：不用扫、不占内存；但搜不到隐藏文件和被排除的目录，子串搜索慢，结果不全。
- **三字母组倒排**：内存大、增量维护复杂；一千万条以内线性扫已经够快。
- **加一个 C 目标写 SIMD 比较**：libc `memmem` 已经够快，不值得多一个目标。

## 后果

- 常驻内存约 60 B/条。依赖目录、隐藏文件、缓存会索引但排在后面。
- MAIO 退出时宿主不通知功能，不能在退出时存盘；靠"扫完存一次 + 有变化时每 30 分钟存一次"，下次启动从存盘时的事件编号回放（不丢变化，只是回放多一些）。
- 多音字在文件名拼音里只用系统给的读音。
- 不索引其他卷（`/Volumes`），外接磁盘留到以后。
