# M7 启动器（FeatureLauncher）需求与设计

> 状态：需求已和用户确认（2026-11-05）。**P1、P2 用户已确认；P3 Everything 语法、P4 命令代码已完成，等用户实测**（ADR-0020、ADR-0021）。路径段规则改用 Cardinal 的（见功能 README）。按第 6 节分阶段实施，每个阶段都交给用户实测。用户已实测 ⌘空格可以从聚焦接管（风险 1 解除）。
> 相关决策：ADR-0005（接管 / 禁用系统快捷键，用来接管 ⌘空格）；ADR-0020（自建文件索引）、ADR-0021（MAIOKit 列出命令，P4 用）。
> 参考项目（都是 MIT，可以借用代码，借用处注明出处并保留版权声明）：
> - `references/oil-find`：**文件索引的主要参考**（Swift，结构和我们最接近，工程质量最高）；

## 1. 用户的决定（原话要点）

- 目标：**系统 ⌘空格（聚焦搜索）的超级版，融合 Raycast**。按 ⌘空格弹出全局搜索框。
- 基础：搜应用并快速打开。
- **全局文件搜索要像 Windows 的 Everything**：输入任何关键词，文件名或路径包含它的结果全部列出。
- 模式：默认全部一起搜；**按 Tab 切换只搜某一类**（只搜应用、只搜文件……）。
- 文件搜索用**自建索引**，参考最完善的开源实现（调研结论：oil-find 的引擎 + Cardinal 的语法）。
- 索引范围：**整个磁盘，排除系统目录**。
- 第一版的来源：**应用、文件 / 文件夹、MAIO 命令和系统操作、网页搜索**。计算器、剪贴板历史、翻译以后再加。

## 2. 功能清单与验收标准

| # | 功能 | 验收标准 |
|---|---|---|
| L1 | 唤出 | ⌘空格在 100 ms 内弹出面板，光标在搜索框，可以直接打中文。再按 ⌘空格、Esc、点面板外面都会关闭。设置里可以改快捷键。第一次绑定 ⌘空格时提示"接管 / 禁用系统聚焦的 ⌘空格"（ADR-0005 已有的流程，可一键还原） |
| L2 | 应用搜索 | 按显示名（中文、英文）、拼音全拼、首字母都能搜到：`wx`、`weixin`、`微信`、`WeChat` 都能找到微信。⏎ 打开（已在运行就切到前台）。新装、删掉的应用自动更新 |
| L3 | 常用排序 | 记录从启动器打开的次数和时间，同样的输入，常用的排前面；同一个输入经常选同一项时，它排第一 |
| L4 | 文件搜索 | 名称包含关键词的文件和文件夹即时列出（每次按键后 ≤ 50 ms 出结果，三百万条以内）。增删改名后 1 秒内反映到结果里。显示图标、名称（命中部分高亮）、所在路径、修改时间 |
| L5 | Everything 语法 | 空格 = 并且、`|` = 或、`!` = 排除、`"…"` 短语、`*` `?` 通配、`ext:`、`file:` / `folder:`、`in:`、`size:`、`dm:`、含 `/` 时按路径匹配（详见 4.3） |

| L10 | 索引状态 | 设置页显示：已索引多少条、占用多少内存、上次完整扫描时间、正在扫描的进度；"重建索引"按钮；没有完全磁盘访问权限时提示并引导去开 |

## 4. 交互细节

### 4.1 面板

- 宽 720 pt，出现在**鼠标所在屏幕**的上 1/4 处；结果最多显示 9 行，其余滚动。
- 可以成为键盘焦点但**不激活 MAIO**（`NSPanel` + `.nonactivatingPanel`），关闭后焦点回到原来的 App。
- 出现在所有桌面和全屏 App 之上。
- 关闭后 5 秒内再打开，保留上次的输入和选中项（Raycast 的做法），之后再打开就是空的。可在设置里关闭。
- 空输入时显示"最近使用"（最近从启动器打开的应用、文件、命令）。

### 4.2 来源和前缀

| 来源 | 前缀（可在设置里改） | 内容 |
|---|---|---|
| 全部 | — | 分组显示：应用（最多 5 项）→ 命令（最多 3 项）→ 文件和文件夹 → 网页搜索 |
| 应用 | `a ` | 只有应用 |
| 文件 | `f ` | 文件和文件夹，等于 Everything 的全部结果 |
| 文件夹 | `d ` | 只有文件夹 |
| 命令 | `>` | MAIO 命令、系统操作、系统设置面板 |
| 网页 | `g ` `bd ` 等 | 直接用对应的引擎搜索 |

- "全部"里分组的数量随结果数调整：某组没有结果就不显示这一组。
- 前缀只在开头、后面跟空格时才算（`>` 不需要空格）。输入 `a` 一个字母不会被当成前缀。

### 4.3 文件搜索语法（Everything 兼容，参考 Cardinal 的 `doc/pub/search-syntax.md`）

| 写法 | 意思 |
|---|---|
| `报告 2024` | 名称同时包含"报告"和"2024" |
| `报告|总结` | 包含其中一个 |
| `报告 !草稿` | 包含"报告"，不包含"草稿" |
| `"Application Support"` | 整个短语（含空格） |
| `*.pdf`、`IMG_????.jpg` | 通配符，匹配整个名称 |
| `ext:pdf;docx` | 扩展名 |
| `file:` / `folder:` | 只要文件 / 只要文件夹 |
| `in:~/Documents 合同` | 只在某个文件夹里找 |
| `size:>100mb`、`size:1mb..10mb` | 大小 |
| `dm:today`、`dm:>2026-10-01`、`dm:7d` | 修改时间 |
| `Library/Application`、`/report`、`report/` | 含 `/` 时按路径段匹配：开头 `/` = 名称以此开头，结尾 `/` = 以此结尾（Cardinal 的切段规则） |
| `( )` | 分组 |

- 优先级同 Everything：`!` 最高，`|` 其次，空格（并且）最低。所以 `a b|c` = `a 并且 (b 或 c)`。
- **不区分大小写**；中文名称按 Unicode NFC 统一后比较（macOS 文件名可能是 NFD，不统一会搜不到）。
- 拼音：只有一个由字母组成的词时，同时按拼音全拼和首字母匹配含汉字的名称（`ht` 能找到"合同.docx"）。
- 语法写错时不报错，把写错的部分当普通文字搜。

### 4.4 排序

**应用和命令**（列表短，可以精细排序）：
1. 匹配质量：完全相同 > 名称开头 > 某个词的开头（含拼音首字母） > 包含 > 拼音包含。
2. 常用度：打开次数按时间衰减（一周减半）。同一个输入选过同一项，额外加分。
3. 正在运行的应用小幅加分。

**文件**（参考 oil-find `coilfind.c:108-206`）：
1. 匹配质量五档：名称完全相同 > 去掉扩展名后相同 > 名称开头 > 词边界 > 包含。
2. 再按这些调整：
   - 加分：在用户目录下、从启动器打开过、是文件夹、最近修改过；
   - 扣分：名称长、路径深、隐藏文件、在依赖目录（`node_modules`、`.git`、`DerivedData`……）或 App 包内部。
3. 结果太多时（> 20 万）只完整排出前 5000 条，界面最多显示 1000 条，并注明"共 N 条"。

### 4.5 应用目录

- 扫描 `/Applications`、`/Applications/Utilities`、`/System/Applications`、`/System/Applications/Utilities`、`~/Applications`（含 Chrome / Safari 的网页 App），以及 `/System/Library/CoreServices` 里少数可以直接打开的（Finder、屏幕共享等，名单写死）。
- 每个应用记：显示名（`FileManager.displayName`，"计算器"）、英文名（`CFBundleName`）、bundle ID、拼音全拼、拼音首字母。
- 用 FSEvents 监视这几个目录，变化后重扫这几个目录（几百个应用，几十毫秒）。

### 4.6 网页搜索

- 默认引擎：Google（`g`）、百度（`bd`）、必应（`bi`）、GitHub（`gh`）。每项是"名称、关键词、URL 模板（`{query}` 处放 URL 编码后的输入）"，可以增删。
- "全部"里最后一项用默认引擎；默认引擎可以选。

## 5. 技术设计

### 5.1 模块结构（`Packages/MAIO/Sources/FeatureLauncher/`）

| 目录 | 内容 |
|---|---|
| `Domain/`（不 import AppKit） | `LauncherQuery`（前缀、来源）、`FileQueryParser`（Everything 语法 → 语法树）、`PathSegments`（按 `/` 切段）、`MatchScore`（匹配质量、排序）、`Pinyin`（用 `CFStringTransform` 生成全拼和首字母）、`Frecency`（常用度）、`ResultGrouping`（"全部"的分组）、`WebSearchEngine`、`LauncherSettings` |
| `Index/`（文件索引引擎） | `IndexStore`（SoA 存储）、`Scanner`（getattrlistbulk 并行扫描）、`Searcher`（分块并行扫名称）、`FSWatcher`（FSEvents）、`IndexUpdater`（应用事件）、`IndexPersistence`（存盘 / 读盘）、`IndexManager`（启动流程、状态） |
| `Infrastructure/` | `AppCatalog`、`SettingsPaneCatalog`（系统设置面板：中文名 + `x-apple.systempreferences:` 链接）、`FileActions`（打开、显示、快速查看、拖动）、`DiskAccessCheck`（是否有完全磁盘访问权限） |
| `UI/` | `LauncherPanel`、`LauncherController`（按键、来源切换）、`ResultList`、`SourceTabs`、设置页（常规 / 文件索引 / 网页搜索 三页） |

### 5.2 文件索引引擎（ADR-0020，以 oil-find 为蓝本）

**存储**（SoA，目标约 50 B/条，三百万条约 150 MB）：
- 所有名称首尾相接存成一整块 UTF-8（NFC + 小写折叠后的一份，用于搜索；显示用原名称时再从磁盘取或另存一份，待实验比较内存）；
- 每条记录：名称偏移 `UInt32`、父目录 `UInt32`、大小 + 类型打包、修改时间 `UInt32`、标志位（目录 / 隐藏 / 包内部 / 依赖目录）；
- **不存完整路径**，沿父目录链拼出来；保证父目录序号小于子项（路径条件、标记清除都能单遍完成）；
- 拼音备用键：只给含汉字的名称算，单独一块，搜索时和名称一起扫。
- 扩展名索引（扩展名 → 记录列表），`ext:` 直接查表（MacEverything 的做法）。

**扫描**：
- `getattrlistbulk` 一次读出一个目录下所有子项的名称、类型、大小、时间，N 个线程共用任务栈，App 里用较低优先级、2～4 个线程，不抢前台。
- 只扫 `/` 和数据卷；进入 firmlink 时按真实设备号和 inode 去重；不跟符号链接。
- iCloud 占位目录（`SF_DATALESS`）只记录不下探，避免触发下载。
- 默认排除：`/System`（应用目录另外扫）、`/Volumes`、`/private/var`、`/private/tmp`、`/Library/Caches`、`~/Library/Caches`、`~/Library/Logs`、`~/Library/CloudStorage`、`.Trash`。设置里可以加减，规则按最长前缀（Cardinal）。
- 外接磁盘：设置里逐个勾选，每个卷一份索引（第一版可以不做，见第 7 节）。

**搜索**：
- 名称块分成若干段，用 `DispatchQueue.concurrentPerform` 并行扫描，先用首尾字节快速筛（SIMD），再确认，丢掉跨两个名称的假命中。
- 新输入是上次输入的延伸时（多打了一个字），只在上次结果里继续找。
- 每次按键给搜索一个版本号，新输入来了旧搜索立即放弃。

**增量更新（FSEvents）**：
- `FileEvents | NoDefer`，延迟 0.15 秒，从存盘时记下的事件 ID 开始回放。
- 事件路径先去掉 `/System/Volumes/Data` 前缀；同一批事件按"最小祖先"合并（Cardinal 实测省掉约 40% 的重扫）。
- 普通事件：重新读这个文件 / 这个目录；`MustScanSubDirs`：重读那棵子树，标记清除删掉没再出现的。只在**根路径**丢事件或 `RootChanged`、`EventIdsWrapped` 时整盘重扫。
- 用 `FSEventsCopyUUIDForDevice` 校验事件库，对不上就整盘重扫。
- **整盘扫描前先开实时流**，扫描期间的事件缓存起来，扫完再补上，避免中间漏事件（MacEverything 在这里有漏洞）。

**存盘与启动**：
- `data/launcher/index.bin`：文件头（版本、卷 UUID、事件 ID、排除列表的哈希）+ 各数组原样写出；写临时文件再改名。
- 启动：读盘（三百万条约 0.3 秒），立即可以搜 → 回放离线期间的事件 → 实时监视。读盘失败、设置变了、事件库对不上就重新扫描；扫描期间应用、命令、网页照常可用，文件组显示"正在建立索引 …%"。
- 每 30 分钟和退出时存盘；超过 7 天自动在空闲时重扫一次。

### 5.3 命令来源（P4，需要改 MAIOKit）

- `CommandRegistrar.availableCommands()`（ADR-0021）：已启用功能注册了的命令 + 所属功能名和图标。
- 需要参数的命令不列出来（第一版）。
- 系统操作：`FeatureSystemActions` 的命令都要填参数（打开 App、运行脚本……），所以锁屏、睡眠、关机、清空废纸篓、切换深色模式等由启动器自己提供。
- 系统设置面板：从系统的设置扩展（ExtensionKit）里读，不写死列表；实现细节见功能 README。

### 5.4 权限

- **完全磁盘访问**：要索引桌面、文稿、下载、邮件等受保护位置必须有。没有时：扫描**跳过这些位置**（不然每个位置都会弹一次授权窗口），设置页和文件组顶部提示"缺少完全磁盘访问，部分位置没有索引"，一键打开系统设置。
- 不需要其他新权限。

### 5.5 性能目标

| 项目 | 目标 |
|---|---|
| ⌘空格到面板出现 | ≤ 100 ms |
| 应用、命令搜索 | ≤ 10 ms |
| 文件搜索（三百万条，输入 ≥ 2 个字符） | ≤ 50 ms；1 个字符 ≤ 150 ms |
| 首次全盘扫描（三百万条） | ≤ 60 秒，期间 CPU 占用不影响前台 |
| 常驻内存 | ≤ 60 B/条 |
| 启动读盘 | ≤ 1 秒 |

### 5.6 风险与需要先做的实验

1. **⌘空格能否稳定接管**：ADR-0005 说 MAIO 运行时可以接管系统快捷键，但聚焦搜索的 ⌘空格还没实测过。P1 第一件事验证。
2. **不激活 App 的面板里输入中文**：`nonactivatingPanel` 成为焦点时输入法是否正常（候选框位置、⌘空格本身是否和输入法切换冲突）。
3. **本机的文件数和扫描时间**：先写一个命令行实验程序（`/tmp/maio-exp/`）跑一遍全盘，得到真实条数、耗时、内存，再定数据结构细节。
4. **NFD 文件名**：确认中文、带重音的名称在 APFS 上实际是什么形式。
