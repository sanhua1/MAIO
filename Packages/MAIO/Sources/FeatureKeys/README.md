# FeatureKeys：按键映射（原名"按键管理"）

替代 Karabiner-Elements 的常用部分，但不做它那一整套规则系统。需求和设计见 `docs/specs/M8-keys.md`，决策见 ADR-0022。

| 阶段 | 内容 | 状态 |
|---|---|---|
| P1 | 设备级修饰键（写进系统的修饰键设置） | ✅ 用户实测 |
| P2 | Caps 分层（全局） | ✅ 用户实测 |
| P3 | 全局改键、鼠标侧键 | 代码完成，待用户实测 |

## 命令

暂无。

## 设置

三个标签，顺序为「Super Caps」「键盘重映射」「其他改键」，默认打开 Super Caps。每页顶部一句话说明用途，说明文字逐条分行（`UI/NoteLines.swift`）。

设置页「Super Caps」（全局 Caps 分层，默认打开）：
- 打开后全局把 Caps 设成"无操作"（HID 事件系统的 `UserKeyMapping`，等同 `hidutil`），不切换大写、不亮灯、单按无动作；
  按下 / 松开由 `CapsKeyMonitor` 从键盘原始输入（IOHIDManager，需要输入监控）读，不受映射影响，不占用任何别的键值。
- 层里每个键：发出一个键 / 组合键（按住 Caps 时的 ⇧⌃⌥⌘ 叠加上去，按住连发），或执行 MAIO 命令（按住只执行一次）。没设置的键照常输出。
- 默认层：W A S D = ↑ ← ↓ →，Q / E = PageUp / PageDown，X / C = ⌘← / ⌘→。
- 窗口切换、截图、录制快捷键等 MAIO 的键盘会话里，层和组合键改键也生效（ADR-0025）：⌥Tab 切换中按 Caps+WASD 就是方向键；层里绑定的命令照常执行，不会把原来的字母交给会话（不会误触切换器的 W 关窗口、Q 退出）。录制快捷键时按 Caps+W 会录成 ↑。
- 关掉分层时删掉 Caps 这条映射（别的 `UserKeyMapping` 原样保留）。

设置页「其他改键」（全局，默认为空）：
- 键盘：一个键（从键表选，或点录制按钮按一下）→「单键」（HID 层，和 Caps 那条一起写进全局 `UserKeyMapping`；可以选 Fn、左右修饰键、F13～F24）/「组合键」/「命令」（event tap 层，按下的修饰键叠加，组合键按住连发）。没有虚拟键码的键（F21～F24、PrintScreen 等）只能换成单键。按住 Caps 时用 Caps 层。
- 鼠标：中键、后退键、前进键、按钮 6～8 → 组合键 / 命令（ADR-0023 的按钮过滤器，原来的功能被替换）。
- 每条可以单独停用。

设置页「键盘重映射」（原名「键盘」）：选一个接着的键盘，五个修饰键（⇪ ⌃ ⌥ ⌘ 🌐）各自改成 ⇪ ⌃ ⌥ ⌘ 🌐 / Esc / 无操作；「还原默认」。

- 不存在 MAIO 的配置里，直接读写系统的修饰键设置（`defaults -currentHost read -g` 里的 `com.apple.keyboard.modifiermapping.<厂商>-<产品>-0`），
  和系统设置「键盘 › 键盘快捷键… › 修饰键」双向同步，退出 MAIO 后仍然有效，键盘重新接上时系统自己应用。
- 只列出接着的键盘（每 2 秒刷新），不列 Karabiner 的虚拟键盘。
- MAIO 看不懂的映射（别的工具写的、MAIO 不管的键）原样保留。

## 权限

辅助功能（改发按键、鼠标按钮）、输入监控（读 Caps 的按下 / 松开）。HID 层属性用 monitor 类型的客户端写，不需要 root。

## 已知限制

- Karabiner 运行时会独占键盘，这里的改动对实体键盘不起作用；页面顶部会提示。只退出 Karabiner 的菜单栏 App 不够，后台的 `Karabiner-Core-Service`（root）也要停掉。
- 系统设置开着时不会刷新，要重新打开那个窗口。
- 键盘固件自己有层的（例如用户自制的 Makey75），按住 Caps 时固件不发 Caps，MAIO 的层不起作用，按到的是固件那一层的键。
- 退出 MAIO 时如果来不及清理，Caps 会一直是"无操作"，直到再启动 MAIO（会按设置重新设）或重新登录。
- 密码框等安全输入时 event tap 收不到按键，层不工作（Caps 按了没反应，字母照常）。
- 写服务属性用的 `IOHIDEventSystemClientCreateWithType` 不在公开头文件里（运行时查找）。
